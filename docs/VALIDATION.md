# Результаты проверки

Локальная среда: macOS arm64, Apple M4, Apple Clang 21.0.0.
Дата: 1 октября 2026 года. `pkg-config` сообщает SQLite 3.51.0 и OpenSSL 3.6.4.
Исходные файлы отформатированы Clang Format; проверка `--dry-run --Werror` прошла.

## Успешные проверки

| Проверка | Результат |
| --- | --- |
| `make` | Обе точки запуска `teller-system` / `atm` готовы; предупреждения компилятора считаются ошибками |
| `make test` | Разбор денег и дат, проценты, категории, история, пароли, права владельца и сохранение прошли |
| `make audit` | Полный внешний сценарий прошёл за 8.551 с на указанной машине |
| `make sanitize` | ASan и UBSan не обнаружили ошибок в модульном прогоне |
| `make analyze` | Clang Static Analyzer: диагностик нет |
| `make stress` | 1 000 000 воспроизводимых мутаций парсеров под ASan/UBSan, ошибок не обнаружено |

Машинный отчёт: [audit-results.json](audit-results.json).
Время зависит от устройства и нагрузки; оно не является гарантией для другого окружения.

## Что проверял внешний аудит

- Пять типов счетов с точными процентами из ТЗ: $5.84, $40.05, $100.12, $240.29
  и сообщение об отсутствии процентов для current.
- Регистрация Marcus, отказ повторному Alice, вход, обновление страны и телефона,
  операции, удаление трёх указанных счетов, передача fixed03 от Alice к Laura.
- Восемь наборов для классификации, включая 59.4%, 59.5%, 59.6%, 39.4% и 39.5%.
- Получение уведомления второй сессией без нажатия Enter: **205.121 мс**,
  включая запуск и авторизацию отправителя. Период опроса приложения — 200 мс.
- Четыре аварийных остановки `_exit(86)`: после изменения баланса, перед COMMIT,
  после COMMIT и после публикации. После восстановления баланс и история
  согласованы, незавершённые снимки удалены.
- 12 повреждённых импортов отклонены, исходные текстовые файлы сохранены.
- 120 операций относительно независимой модели: 112 допустимых записаны,
  восемь попыток снять больше остатка отклонены.
- 16 конкурирующих снятий по $10 со $100 при восьми работающих процессах:
  десять успешных, шесть отказов, итоговый баланс 0 и ровно десять записей.
- Шесть параллельных регистраций одного имени: один пользователь, пять отказов.
- Повреждение текстового представления, ошибка каталога снимков, таймаут блокировки,
  FIFO, повреждённая SQLite-база и рассогласованный баланс обработаны ожидаемо.
- Ввод длиной 10 000 байт, четыре варианта EOF и SIGTERM во время скрытого ввода
  пароля. После SIGTERM эхо псевдотерминала восстановлено.
- Текстовые файлы сравнены с независимыми SQL-запросами по всем полям, включая
  строки операций и номера владельцев. Хеши паролей независимо проверены Python PBKDF2.

## Проверки CI

GitHub Actions запускает `make check` на Linux с GCC и Clang и на macOS.
В Linux включён LeakSanitizer (`detect_leaks=1`). Задание Clang также выполняет
статический анализ, 15 секунд libFuzzer и миллион воспроизводимых мутаций.
Текущий результат находится в [Actions](https://github.com/ernat-soltanbekov/teller-system/actions/workflows/ci.yml).

На локальной macOS Apple Command Line Tools не содержат библиотеку runtime
libFuzzer. Поэтому coverage-guided fuzzing здесь не заявляется выполненным;
его выполняет Linux CI. Локально выполнен отдельный миллион мутаций с теми же
проверяемыми функциями, ASan и UBSan. Это разные методы проверки.

## Пределы подтверждения

Тесты подтверждают перечисленные сценарии, а не отсутствие всех возможных ошибок.
Аварийные тесты моделируют прекращение процесса, а не физическую неисправность
диска или ложное подтверждение `fsync` операционной системой. Целостность SQLite
при таких аппаратных отказах зависит от корректной работы файловой системы.

Учётные данные и суммы в тестах вымышленные. Нет заявления о готовности принимать
реальные банковские операции или о прохождении устной части учебного аудита.
